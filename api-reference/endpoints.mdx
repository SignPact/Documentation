# API Endpoints

This overview reflects the endpoints used by the current frontend. Treat it as a usage map; align any diffs with your OpenAPI before publishing.

<Note>
Authenticated routes require a valid JWT (see [Authentication](/api-reference/authentication)). Some recipient flows use a signature token via query string and do not require Authorization headers.
</Note>

## Base URL

```
http://localhost:8000/api
```

In production, use your deployed API URL.

## Document Endpoints

Based on our frontend implementation, the following document endpoints are available:

### Get User Documents

Retrieves all documents accessible to the authenticated user.

```
GET /documents
```

**Response**

```json
[
  {
    "id": "document_id",
    "name": "Contract Agreement",
    "status": "pending",
    "ownerId": "user_id",
    "owner": {
      "id": "user_id",
      "name": "John Doe",
      "email": "john@example.com"
    },
    "createdAt": "2023-04-01T10:30:00Z",
    "updatedAt": "2023-04-01T10:30:00Z"
  }
]
```

### Get Document By ID

Retrieves a specific document by its ID.

```
GET /documents/:id
```

**Response**

```json
{
  "id": "document_id",
  "name": "Contract Agreement",
  "status": "pending",
  "content": "Base64 encoded document content",
  "version": 1,
  "ownerId": "user_id",
  "createdAt": "2023-04-01T10:30:00Z",
  "updatedAt": "2023-04-01T10:30:00Z"
}
```

### Upload Document

Uploads a new document.

```
POST /documents
```

Request is multipart/form-data (file upload). On success, returns the new document with status `draft`.

### Download Document (embedded signatures)

```
GET /documents/:id/download
```

Returns the signed PDF. Supports signature token query param when used by recipients.

### Get Document Permissions

Retrieves all permissions for a specific document.

```
GET /documents/:id/permissions
```

**Response**

```json
[
  {
    "userId": "user_id",
    "userName": "John Doe",
    "userEmail": "john@example.com",
    "permission": "view" // Can be "view", "edit", "sign", or "share"
  }
]
```

### Share Document

Grants a user permission to access a document.

```
POST /documents/:id/share
```

**Request Body**

```json
{
  "email": "recipient@example.com",
  "name": "Recipient Name",
  "permission": "view" // Can be "view", "edit", "sign", or "share"
}
```

**Response**

```json
{
  "success": true,
  "message": "Document shared successfully"
}
```

## User Endpoints

### Get User Profile

Retrieves the authenticated user's profile.

```
GET /auth/user
```

**Response**

```json
{
  "id": "user_id",
  "name": "John Doe",
  "email": "john@example.com",
  "picture": "https://example.com/profile.jpg"
}
```

> Note: Self‑serve signup is disabled; users are invited or join a workspace.

### User Login

Authenticates a user and returns a token.

```
POST /auth/login
```

**Request Body**

```json
{
  "email": "john@example.com",
  "password": "securepassword"
}
```

**Response**

```json
{
  "id": "user_id",
  "name": "John Doe",
  "email": "john@example.com",
  "token": "jwt_token"
}
```

## Signature Endpoints

### Create Signature Request

Creates a new signature request for a document.

```
POST /documents/:id/signatures
```

**Request Body**

```json
{
  "signers": [
    {
      "email": "signer@example.com",
      "name": "Signer Name",
      "signatureFields": [ { "id": "field-id", "type": "signature", "page": 1, "x": 100, "y": 200, "width": 120, "height": 40, "required": true } ]
    }
  ],
  "message": "Please sign this document",
  "expirationDate": "2023-05-01T00:00:00Z" // Optional
}
```

**Response**

```json
{
  "id": "signature_request_id",
  "documentId": "document_id",
  "status": "pending",
  "signers": [
    {
      "email": "signer@example.com",
      "name": "Signer Name",
      "status": "pending",
      "order": 1
    }
  ],
  "createdAt": "2023-04-01T10:30:00Z"
}
```

### Get Signature Status

Retrieves the status of a signature request.

```
GET /signatures/:id
```

**Response**

```json
{
  "id": "signature_request_id",
  "documentId": "document_id",
  "status": "completed",
  "signers": [
    {
      "email": "signer@example.com",
      "name": "Signer Name",
      "status": "signed",
      "signedAt": "2023-04-02T15:45:00Z"
    }
  ],
  "createdAt": "2023-04-01T10:30:00Z",
  "completedAt": "2023-04-02T15:45:00Z"
}
```

### Recipient token flow

Recipients access signing via `/document/:id?token=...`. The token authorizes limited actions without a bearer token.

## Error Handling

The API returns standard HTTP status codes:

| Status Code | Description |
|-------------|-------------|
| 200 | OK - Request succeeded |
| 201 | Created - Resource was created successfully |
| 400 | Bad Request - Invalid request format or parameters |
| 401 | Unauthorized - Authentication required or invalid |
| 403 | Forbidden - Valid authentication but insufficient permissions |
| 404 | Not Found - Resource not found |
| 422 | Unprocessable Entity - Request validation failed |
| 500 | Internal Server Error - Something went wrong on the server |

Error responses include a message explaining what went wrong:

```json
{
  "error": true,
  "message": "Document not found"
}
```
